## 写作时需要主动纠正的混淆

1. “能调用工具”不能单独证明系统具备自主规划能力。以任务、环境反馈、状态与停止条件解释本书的 Agent 边界。
2. JSON 结构满足约束不意味着参数在业务上合法。读者需要看到路径越界、权限不足及缺少证据等应用层拒绝案例。
3. 检索命中与回答有依据是两个不同指标。分别验证召回结果、引用标识和回答对证据的依赖。
4. 扩大上下文窗口不等于消除检索、裁剪与位置评测需求。结论只能覆盖本次测量的模型与任务。
5. 模拟策略可以教授执行循环，但不能作为真实模型能力的证据。模拟结果、真实调用结果和说明性输出分别标注。
6. 多 Agent 的收益需要与单 Agent 和确定性工作流基线比较。先统计成功率、费用、延迟和交接错误，再讨论采用条件。
7. MCP 规范中的人机交互建议属于教学内容，不构成本项目的执行授权规则。
